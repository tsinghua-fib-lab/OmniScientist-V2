## L3：哲学立场 (Philosophical Stances)

**数量**：固定 4 个节点。P01-P03 是从 L1/L2 归纳的哲学立场，仅通过归纳边
连到 L2 集群；P04 是从 SourceObject 原文直接复制的语气样例，不连任何 L2，
也没有横向边。SoulAgent 全量读取人格内核，不在 L3 层裁剪。

| ID | 名称 | Why / What 问什么 | 理论来源 | 理论是什么 |
|----|------|-------------------|---------|-----------|
| P01 | 科学价值排序 | 科学认知价值相互冲突，他选哪个？ | Kuhn 五价值 (1977) | 科学家共享五条认知价值（准确性、一致性、范围、简单性、丰产性），但它们不是决定选择的算法，而是指导选择的价值——面对同一组价值，不同科学家会做不同的排序和取舍 |
| P02 | 核心信念 | 什么东西他永远不会质疑？什么东西他永远不会做？ | Lakatos 研究纲领 (1970) | 科学的基本单位不是单个理论而是研究纲领。每个纲领有一个不可被经验反驳的硬核，外围有可调整的辅助假说保护带。进步的研究纲领能持续预言新事实，退步的只能被动应付 |
| P03 | 自我认知 | “我是谁”，他的学习经历、就职轨迹和研究领域是什么；他觉得自己是哪种科学家？他和谁是一边的、反对谁？ | 元认知 (Flavell, 1976) | 对自身认知过程的认知——在科学语境下，指科学家对自身思维方式、学术身份定位以及"我属于什么传统、我反对什么传统"的自觉认知；其中客观身份轨迹只能来自已确认身份档案 |
| P04 | 语气 | 他在论文 introduction 或 talk 中亲自怎样措辞？ | 原文 few-shot | 保存 3-5 条逐字原句，让解码器学习句长、节奏、用词偏好与攻击性或谦逊程度；不概括风格 |

**Schema**：

| 字段 | 类型 | 说明 |
|------|------|------|
| node_id | string | `l3_{scientist}_P0{1-4}` |
| level | const | `"L3"` |
| question | string | P01 / P02 / P03 |
| question_label | string | 中文名称 |
| stance | string | 该立场的完整 prose 表述 |
| explanation | string | 用七个“怎么”和具体论文行为解释该立场 |
| considered_L2 | string[] | 生成时实际读取的全部 7 个 L2 节点 |
| summarized_from_L2 | string[] | 归纳自哪些 L2 节点 |
| exemplar_L1 | string[] | 标志性 L1 证据 node_id |
| value_dimensions | object[] | 仅 P01 使用：Kuhn 五个原词、相对优先级及其在此人语料中的含义 |
| identity_context | object/null | 仅 P03 使用：已确认的身份、学习经历、就职轨迹、研究领域及来源 |

P04 使用独立 Schema，不复用上述立场字段：

```json
{
  "node_id": "l3_{scientist_id}_P04",
  "level": "L3",
  "question": "P04",
  "question_label": "语气",
  "tone_exemplars": [
    "来自论文 introduction 或 talk 转录、逐字保留的原句"
  ]
}
```

P04 不含 `stance`、`explanation`、`considered_L2`、
`summarized_from_L2`、`exemplar_L1`、`value_dimensions` 或
`identity_context`。

`stance`、`explanation` 和五价值解释是面向 Coding Agent 的自解释文本，
不得出现 `L1`/`L2`/`L3`、`C01`-`C07` 或节点 ID。结构化引用字段保留
内部 ID，用于追溯和图连接；展示文本必须改写为论文标题、实验行为和七个
“怎样……”的中文名称。

三个 `explanation` 必须分别论证当前问题，不得把七个“怎样”当成固定清单
逐项复述。完整七类模式和全部原始证据是检索范围；正文只保留对当前人格核心
有决定性作用的模式与论文行为。`considered_L2` 记录完整读取范围，
`summarized_from_L2` 记录实际采用的子集。

**示例（Kaiming He）**：

```json
{
  "node_id": "l3_kaiming_he_P01",
  "level": "L3",
  "question": "P01",
  "question_label": "科学价值排序",
  "stance": "简单性 > 准确性 > 丰产性 > 范围 > 一致性。当简单性与范围冲突时选择简单性。复杂度是允许的代价，但必须是可归因的代价。",
  "summarized_from_L2": ["l2_kaiming_he_C02", "l2_kaiming_he_C04"],
  "exemplar_L1": ["l1_resnet_003", "l1_hoi_012"]
}
```

## L2：思维模式 (Cognitive Patterns)

**数量**：固定 7 个节点（每位科学家都有这 7 个类别下的实例化）。**有横向边**（强化/条件/张力），是 SoulAgent 裁剪的入口和传播骨干。

| ID | 名称 | How 怎么做 | 理论来源 | 理论是什么 |
|----|------|-----------|---------|-----------|
| C01 | 怎样定义问题 | 面对一个新问题，他第一步做什么？如何把不可解的问题拆成可解的？ | Kuhn 范式转换 (1962); Newell & Simon 问题空间 (1972); Dunbar 类比推理 (1995) | Kuhn：科学革命的本质不是渐进积累而是范式转换——新范式以不可通约的方式重新定义问题本身。Newell & Simon：问题求解是在问题空间中的搜索，问题的表述方式决定了搜索空间的大小和可解性。Dunbar：在真实实验室中科学家频繁使用跨域类比重新框定问题 |
| C02 | 怎样选择方法 | 假说成型后，他选什么工具？为什么选这个不选那个？ | Hacking 科学推理风格 (1992); Lakatos 研究纲领 (1970) | Hacking：科学史上存在多种不可互相还原的推理风格（几何公设、实验探究、类比建模、分类学、统计概率、历史发生），每种风格有自己的证据类型和真值条件——选方法不是纯技术决策，是认知姿态。Lakatos：研究纲领包含正面启发法（指导做什么）和反面启发法（禁止做什么），构成科学家的操作边界 |
| C03 | 怎样验证结论 | 什么样的实验设计才能真正说服他？他什么时候会说"这不算证据"？ | Popper 证伪主义 (1959); Mayo 严苛检验 (1996) | Popper：科学陈述区别于非科学陈述的标志是可证伪性——一个理论必须做出能被经验推翻的预测。Mayo：证据的强度取决于检验的严苛程度（severity）——一个通过了严苛检验的假说（检验方式极有可能揭示其错误却未成功）才获得了真正的证据支持 |
| C04 | 怎样解释结果 | 什么样的解释能让他满意？什么样的解释他会说"没讲清楚"？ | Woodward interventionist causation (2003) | 科学解释的核心不是描述相关性，而是回答"如果干预了X，Y会如何变化"——好的解释必须揭示因果操纵关系，而非仅报告统计关联 |
| C05 | 怎样判断美丑 | 什么让他觉得一个理论或方法是美的？简洁？对称？统一？出人意料？ | McAllister 科学美学 (1996) | 科学共同体在理论选择中确实使用审美标准（简单、对称、统一、类比性），且这些审美标准本身随科学革命而变化。美不是纯主观偏好——它是科学共同体对理论经验成功的归纳投射 |
| C06 | 怎样处理失败 | 实验失败了他先怀疑什么？他的排查链条是什么？ | Popper 从错误中学习 (1963); Schön 行动中反思 (1983) | Popper：科学进步的本质是从错误中学习——提出大胆猜想，竭尽全力推翻，未被推翻的暂时存活。Schön：专业实践者在行动中反思（reflection-in-action）——当意外发生时，不是在行动外停下来分析，而是在行动中重组理解框架、重新框定问题、现场实验 |
| C07 | 怎样产生想法 | 他的好想法是怎么冒出来的？他怎么判断一个新方向值得追？ | Dunbar 科学推理现场研究 (1995); Kuhn 常规科学 puzzle-solving (1962) | Dunbar：通过对分子生物学实验室的两年现场观察，发现科学创新依赖四种机制——远距离类比生成假说、关注意外发现而非忽视异常、分布式推理（团队>个人）、实验设计启发式。Kuhn：在常规科学阶段，创新不是推翻范式，而是在范式内解决谜题——改进实验精度、把理论应用到新领域、解决反常 |

**Schema**：

| 字段 | 类型 | 说明 |
|------|------|------|
| node_id | string | `l2_{scientist}_C0{1-6}` |
| level | const | `"L2"` |
| category | string | C01-C07 |
| category_label | string | 中文类别名 |
| description | string | 该科学家在这个类别下的具体思维模式描述（1-2段 prose） |
| trigger_contexts | string[] | 什么科学任务场景会激活这个模式 |
| contraindicated_contexts | string[] | 什么场景下这个模式不该主导 |
| supporting_L1_count | int | 支撑证据数量 |

**示例（Kaiming He）**：

```json
{
  "node_id": "l2_kaiming_he_C02",
  "level": "L2",
  "category": "C02",
  "category_label": "怎样选择方法",
  "description": "设计新方法时偏好可检查的简单机制而非堆叠复杂模块。简单本身不是目标，可检查性才是。在多篇关键工作中（ResNet、Faster R-CNN、MAE），他反复通过消融实验证明增加模块不必然带来增益，而消除不必要的复杂度是风险更低的路径。",
  "trigger_contexts": ["architecture design", "method selection", "baseline comparison", "ablation planning"],
  "contraindicated_contexts": ["deploying to production without systematic comparison"],
  "supporting_L1_count": 47
}
```

## L1：科学事实 (Scientific Facts)

**数量**：应取尽取。每位科学家从 evidence card 中转化，200-500 叶子。**无横向边**，每个 L1 通过支撑边挂在某一个 L2 下。

以 Gioia 的 1st-order concepts 为方法论基础——每个 L1 节点直接来自被研究科学家的论文、talk、代码中的原文表述。

## 边类型

### 1. 归纳边 (summarizes) — L3 → L2

**含义**：L3 的哲学立场是从这一组 L2 思维模式中抽象归纳出来的。它不是一条逻辑推导边，而是一条"抽象自"边。

**物理意义**：一个人的底层信念不是凭空产生的——它是对他反复出现的思维操作模式的最高层概括。L3-P01（简单性排第一）之所以在 Kaiming He 身上成立，是因为 C02（怎样选择方法）和 C04（怎样解释结果）反复在 47 篇 paper 里出现。归纳边把"他在做什么"（L2）和"他为什么这样做"（L3）连了起来。

**下游作用**：SoulAgent 不沿归纳边做扩散激活。P01-P03 作为核心原则全量
注入，P04 作为语气 few-shot 全量注入；裁剪不发生在 L3 层。

---

### 2. 支撑边 (supports) — L2 → L1

**含义**：这个 L2 思维模式由这些 L1 科学事实支撑。

**物理意义**：一个人的思维模式不是凭空归纳的——每一条 L2 陈述背后都有具体的 paper、talk、code 中的原文作为证据锚点。当 SoulAgent 生成的 soul.md 被质疑时，可以沿着支撑边一路追溯到"这篇 paper 的第几页第几段"。

**下游作用**：L2 被激活后，沿支撑边拉出该 L2 下归属的 L1 叶子，作为 soul.md 中的证据引述。不沿支撑边做图遍历——L1 是纯叶子，无出边。

---

### 3. 强化边 (reinforces) — L2 ↔ L2

**含义**：当思维模式 A 被激活时，思维模式 B 应被连带激活。A 和 B 不是谁推导谁，而是同一个认知框架的共生组件。

**物理意义**：一个人的思维是整体。Kaiming He 的"怎样定义问题"（C01）和"怎样选择方法"（C02）不是独立的——他把问题重新定义为"消除瓶颈"之后，自然就会选最简单的实现方案。两者不是因果关系，而是同一认知姿态的两个面。在扩散激活理论中，这对应 Collins & Loftus 的"强语义关联"——一个节点激活时，高权重邻居同时被激活。

**下游作用**（SoulAgent 裁剪的核心机制）：
- 当 C01 被 query 直接命中 → 激活沿强化边扩散到 C02 → C02 也被纳入子图
- 这意味着 SoulAgent 不只看 query 直接命中的模式，也看模式之间的自然关联。

**示例（Kaiming He 的 C01 → C02 强化边）**：
```
C01 怎样定义问题          C02 怎样选择方法
"他不是直接优化 SOTA，     "他总选最简单的 baseline
 而是先重新定义问题本身"    对比而非设计复杂新模块"

  这两条不是两条独立的观察。
  他之所以"简单"，是因为他一直在"重新定义问题"——
  把问题定义成"消除瓶颈"后，简单方案自然就是好方案。
  强化边记录了这种共生关系。
```

---

### 4. 条件边 (enables) — L2 → L2

**含义**：用思维模式 B 必须知道思维模式 A。A 是 B 的前提条件。

**物理意义**：某些思维模式之间有严格的先后/前提关系。Kaiming He 的"怎样处理失败"（C06）是"怎样产生想法"（C07）的前提——他的创新路径是：先发现哪里失败了 → 诊断失败的原因 → 提出消除该原因的方案。如果不理解他的失败诊断方式（检查 baseline 实现 → 消融 → 压力测试），看他的"创新"就只是看到一个结果，而非理解他为什么这样创新。

在扩散激活理论中，条件边对应"定向语义通路"（directional pathway）——激活可以从前提流向结果，但不能反向。检查 baseline 能产生创新，但创新的存在不意味着你一定理解了检查 baseline 的过程。

**下游作用**：
- 当 C07 被 query 命中 → 沿条件边回溯到 C06 → C06 也必须纳入子图
- 扩散方向是单向的：C06 → C07，不是 C07 → C06

**示例（Kaiming He 的 C06 → C07 条件边）**：
```
C06 怎样处理失败              C07 怎样产生想法
"实验失败时，他先检查           "他的创新往往来自：
 baseline 实现有没有问题"      发现默认假设是错的 → 重新定义问题"

  如果你不理解他的失败诊断路径，
  你就看不懂他的创新为什么长这样。
  ResNet 的创新不来自"加一些新模块试试"，
  而来自"bare bone 到底在哪个深度开始不行了"的精准诊断。
  条件边确保 SoulAgent 在"怎样产生想法"被激活时，
  不会漏掉对"怎样处理失败"的理解。
```

---

### 5. 张力边 (tension) — L2 ↔ L2

**含义**：思维模式 A 和 B 在特定约束下互斥。两者不能同时主导。

**物理意义**：一个人的价值观内部可以有矛盾——这不是 bug，而是真实人格的特征。Kaiming He 的"怎样验证结论"（C03，要求大范围、多条件、scale 级验证）和"怎样处理失败"（C06，要求快速、精准的消融和单变量排查）在计算资源充裕时不矛盾，但在计算预算紧张时互斥：全面验证需要跑所有对照组，精细诊断需要反复试错，两者争抢同一批 GPU。

在扩散激活理论中，张力边对应"竞争性激活"——两个节点不能同时处于高激活态，否则会产生认知冲突。

**下游作用**：
- **不沿张力边扩散**。激活不传播到另一端。
- 如果两个张力节点同时被激活（一个被 query 命中，另一个被强化边引入），SoulAgent 需要做**语境取舍**——根据当前任务的资源约束（是 Review 任务还是 Exploration 任务），选择激活值更高的那个，抑制另一个。
- 张力边上的 `context` 字段描述了冲突发生的具体约束条件（如 `compute_constraint`、`time_pressure`、`scope_tradeoff`）。

**示例（Kaiming He 的 C03 ↔ C06 张力边）**：
```
C03 怎样验证结论               C06 怎样处理失败
"验证必须经得起 scale 考验，      "失败时，精准的消融实验
 多条件、多数据集、压力测试"      比泛泛的对比更有价值"

  在 GPU 管够时，两者不冲突——先精准诊断、再全面验证。
  在 GPU 紧张时，Kaiming He 的 L3（简单性 > 一切）
  告诉 SoulAgent：优先精准诊断。
  张力边确保 SoulAgent 不会盲目同时塞入两条——
  而是意识到它们有冲突，做出自觉的选择。
```

### 边类型总结

| 边 | 连接 | 方向 | 扩散 | 含义一句话 |
|----|------|------|------|-----------|
| 归纳 | L3→L2 | 单向 | 否 | "这个哲学立场抽象自哪些思维模式" |
| 支撑 | L2→L1 | 单向 | 否 | "这个思维模式有哪些论文中的原文证据" |
| 强化 | L2↔L2 | 双向 | 是 | "这两个模式是同一个认知姿态的两个面" |
| 条件 | L2→L2 | 单向 | 是 | "理解 B 必须先理解 A" |
| 张力 | L2↔L2 | 双向 | 否 | "这两个模式在特定约束下互斥，需取舍" |

### 裁剪的理论基础：扩散激活

KG 中 L2 层的裁剪逻辑直接来源于 Collins & Loftus (1975) 的扩散激活理论。该理论的核心发现是：**当语义网络中的一个概念节点被激活时，激活会沿着链路扩散到关联节点——这些被连带激活的节点虽然未被直接命中，但同样是认知加工的必要组成部分。**

映射到科学家 KG 的裁剪中：

```
Collins & Loftus 的发现               →   KG 裁剪的对应

语义网络中的概念节点                    →  L2 思维模式节点
"面包"激活后"黄油"也被激活（语义启动）   →  直接命中的 L2 连带关联 L2 入选
激活沿强语义链路扩散（启动效应 20-50ms）  →  强化边：连带入选
激活沿条件性链路扩散（须先理解前提）      →  条件边：回溯前提
激活在互斥节点间不扩散（竞争性激活）      →  张力边：冲突检查，不做连带
激活不沿实例节点传播（叶子节点无出边）     →  L1 纯提取，不参与扩散
```

### 裁剪的具体做法

SoulAgent 根据主 Coding Agent 的当前状态（科学任务类型）来决定需要哪些 L2 思维模式。L2-L2 边的角色是：**告诉 SoulAgent，当它基于状态选了某些 L2 之后，其他 L2 应该如何处理**。具体规则：

**强化边**：选了 A 就必须连带选 B。

```
若 A 被任务状态命中:
  → B 也必须入选子图（无论 B 是否被直接命中）
  → 因为 A 和 B 是同一认知姿态的两个面——选了"怎样选择方法"却不选"怎样定义问题"，
    Kaiming He 的"简单"看起来就只是一个孤立的偏好，而不是一个完整的思考方式
```

**条件边**：选了 B 就必须连带选 A（单向）。

```
若 B 被任务状态命中:
  → A 也必须入选子图
  → 因为不理解 A 就看不懂 B——选了"怎样产生想法"却不选"怎样处理失败"，
    就只能看到 Kaiming He 的创新结果，看不到他的创新从哪来的
若 A 被任务状态命中:
  → B 不是必须入选（方向是单向的：前提→结果，不能反向）
```

**张力边**：当 A 和 B 同时入选子图时，检查是否冲突。

```
若 A 和 B 都入选:
  → 检查当前任务的具体约束是否触发了该张力的 context
    例如 C03 和 C06 的张力在 compute_constraint 下触发
    如果当前任务是"快速排查实验失败"，触发 → 保留 C06，排除 C03
    如果当前任务是"设计验证方案"，不触发 → 两者共存
```

**支撑边**：入选的每个 L2，沿支撑边拉出归属的 L1 叶子。不传播，纯提取。这对应扩散激活理论中"激活不沿实例节点传播"——L1 是叶子，无出边。

**归纳边**：P01-P03 始终全量注入，不沿归纳边做裁剪传播。P04 没有归纳边，
只作为 SoulAgent 解码时的语气 few-shot。

**示例**：

```
主 Agent 状态: "用户让我设计一个实验方案来验证新方法"

SoulAgent 判断任务类型 → experiment_design

匹配 L2 trigger_contexts:
  C03 (怎样验证结论) — 直接命中
  C02 (方法选择) — 直接命中

沿边检查:
  C02 —强化→ C03  已命中，无需额外处理
  C02 —强化→ C01  C01 连带入选（强化边：选了方法就必须知道问题怎么重构的）
  C02 —张力→ C06  C02和C06在当前任务下不冲突，无需处理
  C03 —张力→ C06  检查：experiment_design 不是 compute_constraint 场景，不触发

最终入选子图:
  L3: P01, P02, P03（立场全量）+ P04（语气原句全量）
  L2: C01（强化引入）, C02（直接命中）, C03（直接命中）
  L1: 每个入选 L2 拉其归属叶子
```

## 存储知识图谱方案：为什么是 JSON + 索引

### 选型约束

| 约束 | 含义 |
|------|------|
| 规模极小 | 单个科学家 KG：4 + 7 + 200~500 节点，< 1MB，不需要数据库 |
| 读多写少 | SoulAgent 高频读取，蒸馏器低频写入（按月更新），无并发写 |
| 模型无关 | SoulAgent 是 Python 脚本，不需要跨语言兼容 |
| 部署零依赖 | 本机运行，不能要求装数据库服务 |

### 为什么不用以下方案

| 方案 | 为什么不用 |
|------|-----------|
| **Neo4j / 图数据库** | 单科学家几百节点用图数据库是杀鸡用牛刀。需要额外部署、维护、启动开销。SoulAgent 是秒级触发，不能等数据库连接。 |
| **SQLite** | 可以，但关系型表不适合存图遍历——邻接表做 multi-hop 扩散激活需要多次 JOIN，代码比图 API 啰嗦得多。 |
| **纯 Python dict** | 开发中间态可以，但不持久——每次 SoulAgent 启动都要重新构建。且没有边索引，扩散激活需 O(n) 扫描所有边。 |
| **RDF / OWL** | 语义网标准，表达力强但过度繁重。6 个 L2 节点不值得建 ontology。 |
| **NetworkX 持久化** | NetworkX 本身可以 `.gexf` 或 pickle 存图，但调试、审查、diff 都不如纯 JSON 方便。可以作为备选方案 |

### 当选方案：JSON 文件 + NetworkX 内存索引

```
写入（蒸馏器）:
  Python dict → json.dump() → scientist-kg/kaiming-he.kg.json

读取（SoulAgent）:
  json.load() → NetworkX DiGraph 构建（构建时建立 node_id → node 的索引）→ 图上操作
  构建耗时: ~10ms for 500 节点
```

**JSON 的优势**：
- 可直接用文本编辑器检查和 diff（教授想看 Kaiming He 的 C02 写了什么，打开文件即可）
- Git 友好（人格数据库天然需要版本管理——Hinton 2020 vs Hinton 2024 的人格 KG 应该能 diff）
- 零依赖（Python 标准库 `json` + 轻量 `networkx` 即可）
- 单文件，拷贝即备份

**NetworkX 在内存中的作用**：
- 不持久化。每次 SoulAgent 启动时从 JSON 构建，用完即弃。
- 只用于扩散激活的图游走——`nx.dijkstra_path()` 做种子→邻居的加权传播。
- L1 叶子不进入 NetworkX，只在 L2 激活后通过 JSON 中 `parent_L2` 字段匹配拉出。
