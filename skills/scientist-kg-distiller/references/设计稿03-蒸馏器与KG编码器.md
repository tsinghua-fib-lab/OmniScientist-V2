## Phase 1：材料摄取

从多来源收集科学家的原始材料，解析为统一格式的 SourceObject。

| 步骤 | 说明 |
|------|------|
| 1.1 材料发现 | OpenAlex、Semantic Scholar、arXiv、个人主页等多来源发现 |
| 1.2 身份绑定 | 5 种策略交叉验证作者身份，区分同名科学家；同时保存可核验的职业、研究领域、学习经历与就职轨迹 |
| 1.3 全文获取 | PDF/HTML/YouTube 字幕解析为纯文本，通讯作者检测 |
| 1.4 文本规范化 | Title/Year/Venue/Authors/Abstract/FullText 拼接为统一格式 |
| 1.5 材料审计 | 覆盖度检查、解析质量、待审问题清单 |

**产出**：`scientist-corpus/{scientist_id}/` 下的 SourceObject 集合，每份材料包含：
- 全文文本（规范化格式，含章节边界）
- 元数据（来源类型、年份、作者角色）
- 质量标记（解析质量、覆盖度）

## Phase 2：KG 抽取与编码

### 2.1 证据卡抽取：从 SourceObject 到 L1 科学事实

证据卡是从原始材料中锚定在 source 上的科学事实卡片，是 L1 节点的直接前身。

**输入**：每份 SourceObject 的全文文本 + 元数据。

**抽取方式**：LLM 批量读取，判定"这段话里有没有这位科学家的一个具体科学行为/判断——有的话，用一句话记录下来"。

每张证据卡锚定一个科学事实，按四类标注：

| 事实类型 | 说明 |
|---------|------|
| **显式判断** | 科学家在 paper/talk 中明确表达的方法偏好、验证标准、审美判断 |
| **实践习惯** | 通过实验设计、消融结构、baseline 选择暴露的操作习惯 |
| **对比立场** | 与其他方法的对比中暴露的评价标准 |
| **失败归因** | 面对 negative result 或 limitation 时的归因方式和排查路径 |

**输出**：每条科学事实为一张证据卡，schema 如下：

| 字段 | 说明 |
|------|------|
| source_id | 来源标识 |
| source_type | paper / talk / code |
| year | 年份 |
| excerpt | 原文引用段落 |
| location | section + char 范围 |
| observation | 用一句话描述从这个原文中观察到的科学事实 |
| fact_type | explicit_judgment / practical_habit / contrast_stance / failure_attribution |
| author_role | 作者角色（first/corresponding/speaker） |

**数量**：应取尽取，不设上限。

---

### 2.2 从证据卡到 L2 思维模式

**输入**：全部证据卡（跨所有 source，应取尽取）。

**归纳方式**：LLM 分两轮进行。

**第一轮**：将 L1 分入 6 个 L2 类别。

```
给定以下 6 个思维模式类别及其定义：

C01 怎样定义问题 — 如何重新定义问题使其可解
C02 怎样选择方法 — 从问题到方法，为什么选A不选B
C03 怎样验证结论 — 什么实验设计才算"真证据"
C04 怎样解释结果 — 什么解释才是合格的
C05 怎样判断美丑 — 什么让他觉得一个理论或方法是美的
C06 怎样处理失败 — 失败时的排查路径
C07 怎样产生想法 — 想法从哪来、怎么筛、怎么迭代

对每条 L1 事实，判断它属于哪个类别。
一条 L1 只能属于一个 L2 类别（选择最匹配的）。
如果某条 L1 不属于任何类别，标记为 unclassified。
```

**第二轮**：在每个类别内，归纳该科学家的具体思维模式。C01-C07
是 7 个相互独立的模型请求，默认并发执行；每个请求只读取归入该类别的 L1。

```
对 C02（怎样选择方法）类别下的所有 L1 事实，用 1-2 段中文 prose 描述：
该科学家在方法选择上的具体思维模式是什么。
必须基于你看到的事实，不能凭空概括不存在的特征。
同时列出哪些科学任务场景会激活这个模式（trigger_contexts）。
```

**输出**：7 个 L2 节点，每个节点的 `description` 字段是该科学家在该类别下的具体 prose 表述。trigger_contexts 和 contraindicated_contexts 由 LLM 根据该类别下 L1 的分布推断。

**人类复核**：检查 L2 描述是否忠实于 L1 事实。修正过度概括或遗漏。这一步只需要抽查，不需要逐条检查。

---

### 2.3 从 L2 到 L3 哲学立场

**输入**：全部 7 个 L2 节点（每个已填充该科学家的 description）和全部
已接受的 L1 证据卡。P03 还必须读取已确认的身份档案。

**抽象方式**：P01、P02、P03 分成 3 个相互独立的模型请求，默认并发执行。
每个请求都读取完整 7 个 L2 和完整 L1，但只负责一个 L3 问题，避免三个
哲学问题在同一个输出中互相污染。

完整输入是检索范围，不是回答提纲。每个请求只选择对当前问题有决定性作用的
模式和原始论文证据；禁止按七个“怎么”逐项复述，也禁止在三个问题中复用同一
段总览式 explanation。P01 解释价值冲突与取舍，P02 分别解释正面硬核、
反面禁区和知识边界；P02 的 stance 只保存跨论文的抽象方法论，具体架构、
组件、数据集和论文行为只能作为 explanation 中的证据，不能升级成“永不
质疑”的信条。P03 解释身份定位、所属传统与反对对象。

```
基于该科学家在以下 7 个思维模式类别中的具体表现及全部 L1 原文证据：

[依次列出 C01-C07 的 description]

请回答 3 个问题：

P01 科学价值排序：
在准确性、一致性、范围、简单性、丰产性这五条价值中，
这位科学家怎么排序？冲突时牺牲谁保谁？
——从他在怎样选择方法（C02）和怎样判断美丑（C05）中的具体表现为依据。

P02 核心信念：
什么是这位科学家永远不会质疑的正面信念？
什么是这位科学家永远不会做的反面排斥？
他的知识边界在哪里（什么范围外他不碰）？
——从他在怎样定义问题（C01）和怎样处理失败（C06）中的表现为依据。

P03 自我认知：
他是谁？学习经历、就职轨迹和研究领域是什么？
这位科学家认为自己是什么样的科学家？
他和谁站在一边、反对谁？
——从他在怎样产生想法（C07）和怎样验证结论（C03）中暴露的自我定位为依据。
```

P03 的客观身份描述只能来自身份确认阶段，不得从论文内容或常识补全。

**输出语言约束**：L2 description、L3 stance/explanation 和五价值解释会直接
注入 Coding Agent，必须自解释，不得出现 L1/L2/L3、C01-C07 或内部节点 ID。
内部 ID 仅保留在结构化引用字段。模型偶尔输出的缩写引用，只有在可唯一映射
到真实节点时才能转写为论文标题和具体实验行为；无法唯一映射则管线失败。

**人类复核**：身份歧义是唯一强制人工门槛。身份确认后，L1/L2、L3 和横向边
均自动生成；可以抽查，但不阻塞蒸馏。

---

### 2.3b P04 语气提取

**输入**：SourceObject 原文。论文只取 introduction，talk 取转录全文；不读取
L2，也不从 P01-P03 转述。

**提取方式**：LLM 在每份合格原文中找第一人称或评论性表达，逐字复制候选句。
代码逐条验证候选必须是对应 SourceObject 中的连续子串，再从已验证候选中选
3-5 条，覆盖句长、用词偏好以及攻击性或谦逊程度。

**禁止**：生成新句、改写、概括、转述，或输出“该科学家语气简洁有力”一类
风格描述。任何非逐字候选都使该步骤失败并保留审计记录。

**输出**：

```json
{
  "node_id": "l3_{scientist_id}_P04",
  "level": "L3",
  "question": "P04",
  "question_label": "语气",
  "tone_exemplars": ["3-5 条逐字原句"]
}
```

P04 没有 `stance` 或 `summarized_from_L2`，不连接任何 L2。

---

### 2.4 边补全

强化、条件、张力拆成三个相互独立的模型请求，默认并行执行。每个请求系统
检查全部可能的 L2 节点对，并同时读取 description、trigger_contexts 和
contraindicated_contexts；输出全部有文本依据的关系，而不是只挑最显眼的
少数关系。强化边不能只凭“都使用实验/数据”等通用共性；必须证明缺少另一
模式会使人格理解残缺。为避免近似完全图，强化/条件最多各保留 6 条最强关系，
张力最多保留 3 条。每条横向边必须有自然中文 reason；张力边还必须有明确
context，并引用至少一侧的适用或禁用场景来证明约束真实存在。

| 边类型 | 补全方式 |
|--------|---------|
| 支撑边（L2 → L1） | 自动生成——每条 L1 在 2.2 第一轮中已归类至特定 L2 |
| 强化边（L2 ↔ L2） | LLM 判断——给定 6 个 L2 的 description，哪些 L2 是同一认知姿态的不同侧面 |
| 条件边（L2 → L2） | LLM 判断——哪些 L2 是其他 L2 的前提（搞懂 B 必须先搞懂 A） |
| 张力边（L2 ↔ L2） | LLM 判断——哪些 L2 在特定约束下会互斥，标记互斥的 context |
| 归纳边（L3 → L2） | 自动生成——仅 P01-P03 使用各自的 summarized_from_L2；P04 不生成归纳边 |

KG 编码时必须依据当前 L3 的 `summarized_from_L2` 重新生成归纳边，不能沿用
旧边文件中的缓存值，避免单独重跑 L3 后出现陈旧关系。

---

### 2.5 KG 编码

将前序步骤产出的全部节点和边组装为内存图，再从同一内存图同时写出分层
KG 存储和完整 `.kg.json` bundle。纯结构化操作，无抽取或推理逻辑。

```
输入：L1 节点列表 + L2 节点列表 + P01-P03 立场 + P04 语气原句 + 边列表
正式输出：result/{scientist_id}/kg/（分层主存储）
兼容输出：result/{scientist_id}/kg.json（完整 bundle）
```

L1 按其唯一父级的七个“怎么”分为七个 JSONL 文件。编码完成后必须校验：
全部文件哈希、七个分区数量之和、节点/边引用、身份视图与 P03 一致，以及从
分层文件重组的图与 bundle 完全相等。灵魂胶囊只能读取分层主存储。

## 人类参与节点

| 步骤 | 人类角色 |
|------|---------|
| L1 抽取 | 抽查 L1 的 excerpt→observation 是否忠实于原文 |
| L2 归纳 | 抽查 L2 description 是否忠实于 L1 事实，修正过度概括 |
| L3 抽象 | P01-P03 自动生成，可抽查；不作为阻塞门槛 |
| P04 语气提取 | 自动逐字校验，可抽查原句；不作为阻塞门槛 |
| L2 边补全 | 抽查强化/条件边的合理性 |
| KG 编码 | 无需人类参与 |
