# Runtime contracts

Public JSON fields, outcomes, issue codes, and warning codes use `snake_case`. Action names use verb-led `kebab-case`; HTML attributes and CSS properties retain their platform spelling.

## Static HTML gate

Static validation requires a complete HTML5 document, one body-level poster root enclosing exactly one title band, exact verified title and author identity, unique source-grounded content-module ids, a valid physical millimetre page declaration, stable evidence ids and non-empty source metadata, correct prepared-asset hashes, and exact equation bindings. A newly extracted affiliation is rendered deterministically when available and then frozen by the existing scientific identity snapshot; its absence does not add an approval gate for older poster bytes. Static validation rejects active HTML/CSS, remote references, unsafe SVG, unresolved asset tokens, duplicate ids and authored CSS-generated content outside the scientific DOM. Native list-style identifiers and `display:list-item` are supported; Chromium supplies their actual marker text and geometry for editable export. Custom counter-style definitions, list strings/functions/images, and authored `content` remain outside that contract; `content:normal`, suppression and inert counter state are allowed. Every candidate passes this same local CSS rule, while revision snapshots freeze scientific DOM content without a second selector or declaration fingerprint. Static validation does not infer scientific validity or incompleteness from visible English phrases; grounding and selected evidence remain the authority. Each module is one independently placeable evidence job; multiple modules may share a section. Module, section, and evidence bindings do not prescribe visible panels, section count, ordering, rail count, or spans.

Page-size reading resolves the generated single-page contract: unqualified, unconditional `@page` rules with two explicit millimetre dimensions. The parser retains stylesheet boundaries and resolves valid `size` declarations by importance and source order, so an appended override is not mistaken for the old page. This is not a general CSS cascade engine for named/pseudo pages, conditional rules, layers, or computed dimensions.

The deterministic gate checks exact paper identity, prepared-figure hashes, and source-bound equation LaTeX. It does not infer grounding from English locator syntax, legal keywords, or token-level number matching. Evidence planning remains responsible for variant scope, qualifiers, comparisons, and faithful paraphrase from the complete source.

## Paper-source gate

`latex_project_dir` reads the project source directly, following included TeX files and preserving exact display equations, captions, and image files. Use `main_tex` when multiple document roots exist. `arxiv_id` accepts an arXiv id or arxiv.org paper URL and downloads the corresponding PDF for the PDF preparation path.

`paper_path` accepts one local PDF path or host artifact URI. Before authoring, the engine verifies the PDF signature, extracts page-aware text, and prepares a bounded native-Figure provenance manifest plus physically anchored Table or Algorithm visual carriers from the required layout pages. The main model may author source-grounded inline or display LaTeX from the complete prepared paper. Any structured equation inventory is an optional transcription shortcut and never a rendering permission gate. Evidence planning selects only carriers that earn readable poster area; a text- or structured-table-led paper may select none. Formal Table/Algorithm carriers are not silently truncated by type and reuse the existing `figure_sha256s` binding contract. Ordinary layout tables are not converted to images. A single raster XObject that covers the region is extracted without re-encoding; mixed or vector content becomes a self-contained SVG crop; 450 DPI PNG rendering is the final fallback. A horizontal PDF separator that covers the caption-owned graphic component bounds text ownership before padding, so a preceding table row cannot leak into the next figure while labels inside the new ownership cell remain attached. Extracted captions and bounded discussion context describe each `asset://N`; selected image bytes are embedded into final HTML. Missing PyMuPDF returns a recoverable `missing_capability` result and no authoring model call is made.

Draft and approval source preparation invoke this same extractor once in a fresh process of the active Python runtime. Host PDF-reader globals cannot change the prepared source, and cancellation of asynchronous preparation terminates its owned child. This is a runtime isolation boundary, not a second parser or validation pass.

Image-region candidates use PyMuPDF's native clipped page bounds, not the full placement bounds of an image XObject. Vector paths likewise intersect their active PDF clip stack before they participate in figure clustering or crop extent. The shared PDF runtime requires PyMuPDF 1.28 or later, a verified baseline for this behavior. Lossless raster extraction continues to compare original placement bounds with the crop; other regions use the existing vector/raster crop path.

## Design-reference gate

After evidence and page planning, every draft resolves exactly one visual reference before HTML authoring. Complete `OMNI_IMAGE_GEN_*` configuration calls the Omni-normalized image endpoint only when a usable VLM can interpret the content-free result; otherwise deterministic content-shape signals select one of five bundled real conference-poster seeds. The browser-independent estimator fixes the automatic direction first. Seed selection happens once inside that direction and never compares references by whitespace or fit. Image generation and VLM review use independent endpoint/model/key triples even though generated pixels require a consumer. These examples provide design evidence, not templates, semantic slots, fixed columns, or scientific evidence.

The main model selects evidence and owns its interpretation. One optional VLM observation of already-selected figures describes only their panel structure, embedded-text density, internal legibility pressure, and whether each intact figure needs a normal column, a wide region, or dominant page width; the existing page-capacity audit uses those observations alongside the complete source, never as scientific authority. The estimator consumes that width need as content pressure rather than a pass threshold: two ordinary figures do not share one notional column, while wide or dominant figures are costed as stacked continuous regions. The audit may retain or omit a draft-selected figure but cannot introduce a new source figure; visual observations change allocation pressure only. Its revised ContentBudget uses the same prepared-figure, equation and schema normalization as initial planning. The initial author receives the retained observations as allocation evidence so a dense essential figure can displace secondary material and receive enough continuous area. The final main-model audit is the scientific QA boundary. Initial authoring preserves its modules, copy, figures, tables, equations, roles, priorities, source labels, and qualifiers exactly while the selected Author owns visual composition. Page estimation and seed selection do not ask the VLM to decide scientific content. Once the single reference exists, the VLM observes that image without the target-shape signals used for selection or generation. It describes actual source regions and approximate proportions alongside hierarchy, rhythm, typography, surfaces, boundaries, and figure treatment. These are source observations, including local exceptions and uncertainty, not fixed target positions or semantic slots. The VLM does not compile typed layout, palette, CSS, HTML, or target coordinates. The selected main or vision Author receives this brief, the target page and a neutral scientific-content carrier, then owns the complete HTML/CSS composition without reopening scientific editing. Identity, selected mathematical content and prepared-asset membership remain deterministic constraints. Subsequent visual revisions bind to the selected candidate, not the initial outline. Blocking output-contract diagnostics return to the same stateful editor while time remains; the first candidate that clears them passes to the independent visual reviewer, which owns aesthetic iteration and pairwise quality comparison. If reference interpretation remains unavailable after its bounded transport retry, authoring continues without pixel-derived reference observations and the result remains explicitly unapproved; the runtime does not invent a fallback layout or visual pass.

The returned `design_reference` is an exact hash-bound object used by authoring and its durable checkpoint. Final visual review does not receive or bind it. Its pixels and text cannot source claims, numbers, authors, affiliations, equations, figures, citations, logos, or venue identity. Its image hash is never a prepared source-figure hash and never contributes to `source_figure_manifest_sha256`.

## Chromium gate

Chromium verifies that the poster can be reviewed safely. Its hard boundary covers root/id/page measurement, blocked network requests, missing visible title/content/modules, any selected source figure that is invalid, hidden, unrendered, clipped, or outside the poster, rendered text or media outside the physical page, self-clipping or scroll-constrained element overflow, overlap between independently movable poster modules, source-figure overlap with editable text, native-table overlap with its neighboring heading or caption, and visible poster elements outside the physical page. Physical-page containment uses the browser's text ranges and media bounds, including identity outside scientific modules; an empty layout container extending the root's scroll area does not by itself prove content loss. A source-figure/text collision reports the colliding text element, exact line and figure rectangles, and which figure edge is crossed; it does not choose the repair. A table collision likewise reports only the measured table and neighboring text boxes. Ordinary auto-height, `overflow:visible` module flow is not a separate blocker; the poster root owns physical-page containment. Physical figure extents and image-box ratios, other geometry diagnostics, physical type size, and page-fit measurements remain local context rather than deterministic aesthetic blockers. Whole-page figure area percentage is used only to prioritize detail crops. Code-derived typography targets remain authoring context and advisory browser diagnostics. Neither is exposed to the VLM as an acceptance signal; the reviewer receives actual physical type distributions instead. No universal figure-label target or derived readable flag is exposed to the VLM as an acceptance target.

Chromium does not decide whether the poster is attractive, readable at conference distance, dense enough, too card-like, balanced, or visually hierarchical. It records measurements and repair context for the candidate-and-screenshot-bound visual review. If Playwright or Chromium is unavailable, return `missing_capability`; never pretend rendered QA passed.

Residual-space observations use actual rendered container boxes and painted content, not inferred page lanes. Nested or coincident measurements retain their module ownership when consolidated before selection. These are local spatial facts for review, not a complete map of whitespace or a layout acceptance threshold.

## Reference-aware visual-review gate

Reviewer `strengths` and `global_directives` are optional audit fields. The shared result boundary normalizes absent fields to empty arrays without another model call; supplied values, verdict consistency, actionable issues, and exact artifact bindings remain validated.

`inspect` writes one canonical `inspection.json` beside its screenshot and visual-evidence bundle. `prepare-visual-review` requires that file and the exact candidate HTML, then derives the physical page, current grounded module bindings, rendered-inspection issues, screenshot, and Chromium evidence without a second caller-authored summary. It creates `scientific-poster.visual-review-request.v9`, binding the candidate screenshot, current evidence, sequence number, optional incumbent screenshot, and visual criteria. Reference pixels and plan prose are consumed once during initial authoring. The built-in operational reviewer judges the current rendered visual state without receiving a body-text transcript or historical authoring plan.

The verbatim `input` and caller `feedback` remain authoring instructions. Final visual review independently judges the current screenshot, displayed content, and measured evidence; it does not replay historical defect reports or receive the initial raw visual-design plan. The reviewer receives current displayed copy and rendered measurements. The final main-model ContentBudget audit owns source fidelity; visual review does not repeat the paper or certify scientific truth. Reference hashes remain provenance and receipt bindings. The adapter applies the current shared review instructions and excludes historical authoring context.

An image-capable harness returns `scientific-poster.visual-review-result.v9` with the same candidate and evidence bindings; the receipt is `scientific-poster.visual-review-receipt.v9`. The adapter verifies the original full-resolution screenshot hash, then sends a bounded whole-page overview so local vision models do not spend the review budget decoding poster-scale pixels. A revision review sends the incumbent and proposal together, followed by the optional communication-quality reference, so one judgment records `improved`, `unchanged`, or `regressed`. A local gain does not count as improvement when another material dimension becomes worse. When the endpoint preserves independent image inputs it also sends an optional labeled high-resolution source-figure atlas. The custom reference is not scientific evidence or a required layout. The reviewer must reject a clearly material and correctable gap in scanning hierarchy, visual explanation, or finish without requiring the reference's exact objects or styling. A pass cannot simultaneously report a noticeable quality deficit against that reference. The overview establishes whole-page hierarchy and placement; exact Chromium observations and any atlas support closer detail reading without changing the delivered physical scale. The central claim, explanatory copy and decisive evidence must work for a standing reader at about one metre; image zoom cannot establish print readability. Source figures remain immutable image leaves: they may be moved or resized intact, never cropped, redrawn, or internally edited. A reviewer may cite their observations as evidence, but an editable target is an owning module or the poster root; restyle/reflow cannot redraw internal legends, axes, labels, panels, or pixels, while `content-replan` may compress surrounding grounded copy without editing figure pixels. Each model-authored issue contains only criterion, target ids, and operation. The host binds relevant immutable observations by criterion and target when it creates the receipt, so the vision model never copies machine ids or repeated measurements. Layout-solution prose is intentionally absent from the issue contract. A pass requires no critical issue or global directive. `OMNI_VLM_ENDPOINT` accepts an OpenAI-compatible API base URL or a complete chat-completions URL; the Skill appends the standard path to a base URL, uses bearer auth, and never infers a provider. Scores are diagnostic rather than pass thresholds. A revise result routes one or more issues through `restyle`, `reflow`, or `content-replan`. Sequence numbers are audit metadata; they do not turn resource exhaustion into a quality verdict.

Every candidate with a screenshot and stable Chromium evidence is eligible for VLM review, including a geometrically defective draft. Its request carries the exact screenshot and browser observations; supported reviewers may also receive a bounded detail atlas. A candidate that still has a deterministic blocker remains exportable as an explicitly unapproved partial draft, and the VLM cannot pass it. A final pass requires deterministic integrity and the VLM verdict on the same bytes. The receipt's concise summary describes the visible current-state defect and reading impact without prescribing a placement or topology. The author receives that diagnostic summary together with criterion, exact target ids, operation, and host-bound observations; strengths and solution prose remain human audit context, so the reviewer routes a defect without owning its layout solution. For each visual edit batch the selected Author chooses exact replacements, a complete stylesheet, or an atomic wrapper shell containing references to the exact current title and module nodes. A targeted content-replan returns to the main scientific editor. The host stages the proposal and returns static and Chromium feedback. A proposal replaces its deterministic incumbent only if it clears the blockers or reduces them without adding or increasing another blocker; a changed parent-layout relationship may advance the candidate only when comparable measurements do not worsen. A render with exactly the same screenshot pixels is not promoted to VLM review. Unselected proposals leave the incumbent HTML and live preview active, not only its result metadata. After a VLM verdict, later edit checks also report each source figure's reviewed and current physical extents plus the delta. The complete scientific snapshot remains frozen while intact modules may move or change span. `content-replan` may additionally curate or compress only body text, ordinary detail points, and method-step details in the exact grounded modules named by the review; method-step labels and order, headings, takeaways, captions, tables, equations, identity, evidence, and non-target copy remain frozen. The structured-copy tool rebinds unchanged inline LaTeX to its original frozen MathML, so surrounding prose can change without opening formula authority. While receipt-targeted copy modules remain pending, the editor exposes only this tool; layout and finish tools open after every named copy target has produced a checked change. It may omit secondary examples or repeated detail, but cannot alter a retained value or qualifier, invent content, or delete the module. The outer workflow promotes a rendered proposal only when the pairwise VLM review marks it improved. An unchanged or regressed proposal leaves the incumbent active and feeds a different-strategy instruction into another edit while the shared deadline remains; it never replaces the better version. The loop stops on pass, unavailable review or authoring, or resource exhaustion. Accepted inspection and review artifacts are reused during publication rather than rerun on the same bytes. If authoring or revision cannot finish safely, return the exact prior bytes and durable checkpoint. With no configured reviewer, return `visual_review_unavailable` with `visual_review_mode: deterministic-only`. A configured but unavailable VLM remains `vlm`/`awaiting-review`; a completed non-passing review remains `vlm`/`revision-required`. Either state may still export a statically valid authored draft with its actual inspection defects, while approval remains unavailable without a passing receipt.

VLM `restyle`, VLM `reflow`, manual `full-layout`, and `content-replan` produce a complete valid candidate through the shared editor tools. Full-layout editing keeps scientific copy readable to the author and tokenizes only embedded image bytes, so the model can compose around actual content without carrying binary payloads. The layout-shell tool lets wrapper topology and CSS change together while the host reinserts frozen scientific nodes. A `data-poster-ref` is an empty replacement marker: layout classes, styles, and surrounding content belong on its retained parent wrapper, and the host rejects placeholder attributes it would otherwise discard. Initial HTML editing freezes its selected evidence. During automatic drafting, measured capacity failure may return to the main scientific editor for a new complete ContentBudget, then start another HTML composition on the same measured sheet. Public revisions of a selected poster keep their scientific snapshot frozen, with copy authority opened only for receipt-targeted `content-replan`. Every author revision receives the already stored relationship-level ReferenceAnalysis alongside the current HTML and user direction. This retains initial design context without authorizing a new restyle or reinterpreting reference pixels; current explicit user changes take precedence. The operational reviewer receives the incumbent, proposal, and, when supplied, the custom quality reference in one call. A candidate that passes geometry remains publishable as an explicitly unapproved draft even if its VLM review requests changes. If initial drafting stops before geometry passes, deliver its latest statically valid authored candidate as partial; failed public revisions retain the existing published draft. Staged edits save their own sidecars and cannot update an unrelated active checkpoint. Revisions read the selected HTML's embedded figures and bound source text without requiring the original asset paths. VLM-directed `content-replan` only compresses or reorganizes current copy in the named modules; explicit user-directed `content-replan` may also correct or clarify that target copy from the complete bound source. Deterministic comparison freezes identity, module instances, source bindings and figures, displayed MathML, equations, semantic roles, priorities, visual kinds, and the exact rendered physical page. Automatic page estimation is consumed before initial authoring. Render-driven content replanning retains the measured sheet while changing its carrier selection. Visual revision may shorten an adaptive sheet after Chromium verifies the resulting layout; user-fixed dimensions remain unchanged.

After authoring, HTML is the current editable copy. The checkpoint's `content_budget` is the initial plan, not current prose or an independent scientific authority. Review briefs derive current module/source bindings from the selected HTML and omit the body-text transcript and whole paper, so visual readability is judged from the rendered image. Candidate checkpoints store the contract belonging to those exact bytes, including when the editor falls back to an earlier candidate. Published results do not return the original budget as current content. Decision targets use `page_plan.content_contract.modules`, and an `author-ready` recovery reuses the exact saved HTML. `estimate` and pre-author recovery still return their content budget.

Background execution never waits for an operator. When configured review requests a change, the result may include `scientific-poster.decision-request.v2`, bound to the current HTML hash. Each actionable option carries its own continuation: layout revision uses `full-layout`, while grounded copy compression uses `content-replan` plus exact `content_replan_targets`; `keep-draft` has no continuation. A later ordinary `revise` invocation copies the selected option's continuation and adds its required fields. Deterministic-only operation without a configured VLM does not create this checkpoint.

## Estimate and page-fit contract

`estimate` returns `estimate_complete` with the normalized `content_budget`, `page_plan`, source summary, expected figure hashes, and warnings. Source-only portable calls return `host_agent_required`; callers may supply a prevalidated grounded budget for deterministic portable estimation.

Explicit pages reject non-object, missing, non-finite, non-positive, or out-of-range dimensions through `invalid_page`. Evidence-budget validation protects structure, grounding, and prepared-figure identity; its pre-reference capacity estimate is an orientation and starting-size heuristic rather than visual acceptance. Draft-selected figure width needs contribute to that heuristic so the main-model audit can make an informed editorial cut; they never delete evidence by themselves. Neither structural normalization nor frozen-copy comparison certifies the truth of claims. During each HTML composition, the selected Author and the renderer preserve the current source-grounded, page-audited scientific carrier exactly. Automatic drafting may return to the main scientific editor when rendered capacity evidence shows that the carrier selection itself needs revision. Focal emphasis, typography, density, grouping, and topology remain open design decisions inside the audited inventory.

An auto page plan starts from common academic bounds and estimates content pressure without compiling layout. The host author chooses one complete composition inside that canvas from the pixel-derived reference brief and the target modules' actual depth. Chromium remains authoritative for final overflow and containment. A user-specified physical page is a hard geometry and capacity contract. Final VLM review judges the actual candidate and current user direction, not conformity to initial planner values. Page estimation never asks for filler.

## Selection state

The checkpoint `authoring_request` preserves the original user direction
across revisions. The author receives it through the existing content brief's
`user_direction`, separately from the current caller and reviewer feedback. Current
explicit user changes take precedence; unchanged requirements and accepted design
decisions remain in effect. Versioned checkpoints require this field. This does not add
reference prose or historical authoring context to the operational image reviewer.

The preview proxy injects its overlay only into the served response. `poster.html` bytes remain unchanged. A valid machine-owned selection stores:

- source HTML SHA-256;
- selected stable poster id, nearest poster module, semantic roles, and module priority;
- bounded text sample, rectangle, and computed styles;
- capture timestamp.

The server rejects stale hashes and identities that do not exist in canonical HTML.

## Approval and handoff

The returned poster approval phrase is `APPROVE SCIENTIFIC-POSTER poster <html_sha256> source <grounding_source_sha256> figures <source_figure_manifest_sha256>`. Approval accepts exactly one grounding input and one passing visual-review receipt bound to the same HTML hash. With `paper_path`, it deterministically reconstructs page-aware text and prepared-figure hashes; with text input, the caller supplies `source` or `source_text` and machine-owned figure hashes. Approval repeats static grounding and prepared-figure validation, then verifies the already-rendered receipt against the exact HTML hash; it does not launch Chromium a second time. The content-addressed bundle contains exactly `poster.html`, `visual-review.json`, and `approval.json`.

The approval result returns the verified receipt path, exact HTML path, and content hashes for downstream handoff.

## Editable PPTX export

The direct `export-pptx` action accepts exact validated HTML and an output directory; it does not require an approval or visual-review receipt. In the normal Omni `draft`/`revise` flow, automatic export attempts the delivered statically valid draft even when deterministic inspection reports layout defects. Reviewer availability or a subjective revise verdict changes approval and revision state, not whether the authored candidate can be serialized as an explicitly unapproved editable PPTX. Inspection failures remain attached to the partial result; export success does not turn them into a visual pass.

Chromium captures a versioned scene with stable object ids, physical slide geometry, native text, native tables, semantic MathML equations, module/title shapes, and figure images. The Python renderer uses `python-pptx` to write one custom-size slide; it never places a full-poster screenshot on the slide. MathML becomes native editable Office Math without an image fallback. OpenXML verification confirms one slide, retained object names, and native equations.

Native HTML cell spans become native PowerPoint table merges. Browser-measured cell edges determine column widths; covered grid cells remain empty so merging cannot duplicate or lose scientific text. Origin cells may carry ordered native text runs whose concatenation exactly reproduces the authoritative cell text, including authored line boundaries; covered cells never receive those runs. Plain scenes without cell runs retain table-cell styling compatibility. Math inside a cell retains its separately measured native Office Math object.

Outside ordinary native table-cell runs, mixed measured content and native list markers are preserved as editable, browser-measured text carriers, including the existing list/math/nested-table cell path. List numbering, marker glyphs, font runs and positions come from Chromium's layout snapshot, not a second numbering or placement algorithm. Preflighted line fragments keep their captured size without a second native autofit; ordinary text retains its existing fit behavior. These measured carriers preserve the rendered layout, not paragraph-level reflow after editing long text or replacing fonts.

The export gate blocks failures of basic editability: no native text, a raster image covering at least 80% of the page, text boxes that can grow beyond captured bounds, or broken required object identity. Slide bounds, missing portable-font preflight, and native-object overlap are warnings; the reference-aware visual review owns layout and readability judgments. Every failure or warning names the affected object and a suggested patch. The result returns `poster.pptx`, `poster-scene.json`, `poster-pptx-rubric.json`, and OpenXML counts.

HTML remains the canonical authoring state; the PPTX is its directly exported editable delivery companion.
