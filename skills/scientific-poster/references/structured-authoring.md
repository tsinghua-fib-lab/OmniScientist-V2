# HTML authoring

`poster.html` is the sole poster authoring state. Produce it directly; do not ask a user or model to fill a per-poster JSON form.

## Read the paper before composing

Build a mental evidence map from the complete supplied source:

1. What problem motivates the work, and why is it hard?
2. What is the central contribution in the authors' own evidentiary terms?
3. Which method detail is genuinely novel or necessary for interpretation?
4. Which results most directly establish the contribution?
5. What conditions, baselines, units, uncertainty, and scope qualify those results?
6. Which figure, table, or compact HTML/SVG diagram best carries the argument?

Prefer evidence stressed in the paper's result discussion, principal tables, and figure captions. Do not select content merely because it fits a convenient panel.

Audit every planned claim at its exact experimental scope. Keep base, large, ablated, and task-specific configurations distinct; retain the dataset, hardware, protocol, estimate status, uncertainty, and exceptions that qualify a comparison. Preserve hypotheses and words such as “may”, “appears”, and “seems” at the same epistemic strength. If narrative prose conflicts with a displayed table, report the table's literal values without repeating the disputed ranking. Interpret only prepared figure hashes that are actually visible with the discussion; otherwise show the missing evidence or omit the observation.

When the source is a local PDF, give `paper_path` to the Skill instead of reading the binary through a text-file tool. PDF preparation is a distinct pre-authoring stage: page-aware text and bounded visual carriers become the model's source and optional visual assets. The same first-page geometry may recover optional verified affiliations only from the author-to-Abstract identity band or a numbered organization footnote at the page bottom; it stops before contact, proceedings, copyright, or body text, and never guesses venue branding from an institution. Associate complete text objects with the artwork and its nearest caption; preserve labels above or beside a figure and legends before the caption without pulling in clipped neighbouring prose. A horizontal separator spanning the owned graphic component starts a new object-ownership cell: text above it belongs to the preceding object, while complete labels below it may join the figure, and crop padding never crosses back over that boundary. Caption discovery works at native line level even when prose precedes it in the same text block, and aligned short panels are grouped under that caption before figure-size filtering. Distinct physical captions keep distinct asset paths even when figure numbers repeat. Preserve a covering raster XObject without re-encoding, preserve mixed or vector content as a self-contained SVG crop, and use a 450 DPI PNG only as fallback. After native Figure extraction, the same isolated worker uses the local layout reader to complete captions and recover bounded `pdf_table` and `pdf_algorithm` visual carriers. A Table carrier requires a preceding picture with no intervening caption; an ordinary structured table remains text. An Algorithm carrier ends at the next section boundary. Never put a PDF formula crop into the poster. When the paper carries a first-page arXiv version stamp, the source adapter may retrieve title-matched arXiv HTML and expose renderable LaTeX as optional `source_ref` transcription shortcuts. Missing enrichment preserves the native result and does not disable source-grounded mathematical authoring by the main model. If the PDF reader itself is absent, stop with the returned installation command; never treat the user's request string as paper content.

## Choose composition from the evidence

- Figure-led is useful when one decisive visual deserves the largest uninterrupted region.
- Method-led is useful when architecture, procedure, or study design needs the clearest spatial flow.
- Result-led, balanced, asymmetric, or multi-entry compositions may fit other evidence distributions.

These are descriptive emphases, not closed layout modes. Semantic roles never become fixed slots. The reference interpreter observes one exact image without target content shape or role weights. It returns transferable spatial grammar grounded in the source's actual regions, count, arrangement, approximate relative proportions, dominance, grouping, rhythm, and open versus enclosed treatment. These are source observations, not a code-prescribed target topology. It distinguishes heading-only treatments from whole-region surfaces and records local exceptions and uncertain type details rather than inventing them. The host text model receives the target content, page and user direction separately. It reproduces the observed design relationships when replication is requested, or adapts topology, type, color and surfaces to new content when adaptation is requested. The interpreter does not compile lanes, colors, CSS, or coordinates for the target, and reference pixels never supply its scientific content or identity. If pixel interpretation is unavailable, authoring may continue from the grounded carrier without those observations, but the result remains explicitly unapproved until rendered visual review succeeds.

The page plan reports physical capacity and a coarse balance estimate, not a semantic grid. The model chooses track count, grouping, spans, and local subgrids from actual copy depth, figure density, and semantic importance. It must not give a sparse module a full-height lane while deeper modules crowd elsewhere or pin a footer so that it manufactures empty canvas. A figure's continuous width need controls horizontal measure only; the rendered carrier and its explanation determine module depth. A wide shallow carrier belongs in an intrinsic row or beside other retained content, not vertically centered in an oversized fixed row. Public `estimate` remains browser-independent and supplies only an orientation and starting-size heuristic. Chromium is authoritative for exact rendered overflow and containment; it measures the authored result and never places modules. A user-specified physical page remains a hard capacity contract.

Make scan groups immediately distinguishable through group-level cues such as title treatment, a thin rule, local background tone, shared boundary, or deliberate inter-group whitespace. A repeated section vocabulary may consistently use one cue across groups; hierarchy still comes from content, scale, placement, and evidence. Do not add a second fixed card treatment around each individual module.

Use native list styling for bullets and numbering; Chromium's actual markers export as editable text. Use sequence numbers for actual ordered processes, not unordered claims or provenance. Authored symbols and connectors belong in real DOM elements, not CSS pseudo-content. `aria-hidden="true"` controls accessibility exposure, not visual visibility or permission to change printed text.

Before authoring, create a grounded evidence map with the central contribution, the method detail needed for interpretation, complementary decisive evidence, provenance, literal source locators, and only prepared source-figure hashes. Let evidence determine the number and granularity of scan groups and modules. `scan-first`, `figure-led`, `method-led`, `result-led`, and `narrative` are optional organizational descriptions, not schemas. Groups do not need to form a linear problem-method-result sequence. Include a limitation, boundary condition, or negative result only when the source supports it; never invent one to satisfy structure. Locators are audit metadata: visible copy explains the evidence and captions tell the reader what to notice. Do not print `Figure N`, `Table N`, page/section labels, or a `Source:` line beside every visual; consolidate literal locators in provenance/references. Combine closely related material rather than creating one panel per paragraph or metric. A `table` module carries `table={"columns":[...],"rows":[[...],...]}` with literal string cells and one cell per column. Shared measures, units, and direction appear once in the header; methods or conditions appear in the first column. Preserve qualifiers in cells or one shared protocol sentence. The renderer uses a native HTML table and the existing editable PPTX table exporter. Use a matrix only when repeated rows under shared measures answer one lookup or comparison question; choose rows and columns for that stated question while retaining every entry whose omission would change its scope, qualifier, or conclusion. Use metric callouts for independent outcomes, without a table-count or row-count quota. Select prepared visual carriers by distinct evidentiary function; there is no global figure-count cap and no fixed module placement. Scientific nonredundancy alone does not justify poster inclusion. When one sourced sentence or value carries a supporting role, leave the figure unbound and use open space to enlarge stronger evidence. The focal entry is the carrier a standing reader can understand first: a definition, condition, or equation that needs preceding context remains primary, while an overview, architecture, or comparison figure that directly exposes the paper's new object or mechanism may be focal. A self-contained formal result may remain focal when it does not require an earlier module. Each module owns one scientific quantity or relationship within one coherent comparison frame. A secondary field is auxiliary only when it decodes the primary carrier or gives its exact values from the same observations, metric, and protocol; otherwise separate the independent decision or select the stronger carrier. Let each selected figure, table, equation, or flow do most of its own explanatory work: use at most one verbal channel for a missing reading key, material qualifier, or concise consequence, and never transcribe the caption or walk through every panel. A prepared process figure is primary only when its ordered relationship remains understandable without panel-local prose; otherwise omit it and use a native method-flow. A retained `method-flow` is an editable sequence or relationship schematic; rendering the same steps only as prose or a list discards that planned carrier. Treat the pre-reference typical column as composition context, not an evidence-selection or readability gate. Run `estimate` when no exact venue page is supplied. Plan content from the complete source and supplied physical capacity. When an image-capable reviewer is available, observe only the selected figures' panel structure, embedded-text density, scaling pressure, and continuous width need. The estimator uses that width need as content pressure rather than a readability verdict. The page audit may retain, omit, or select another prepared source figure when the complete paper supports its evidentiary role; appearance does not establish scientific importance. Pass retained observations to the initial author as allocation evidence. The main-model page audit is the scientific QA boundary. Initial HTML authoring preserves its modules, copy, figures, tables, equations, roles, priorities, source labels, and qualifiers exactly while the selected Author owns visual composition. Structural validation does not certify scientific interpretation. Final figure legibility is still judged on the rendered poster at its actual allocated size.

Use `visual_kind: figure` for a prepared process or architecture image. Use `visual_kind: method-flow` only for a native editable sequence, represented as `flow_steps: [{"label":"short node label","detail":"one direct transition or result"}]`. A method-flow does not carry `detail_points` or a source figure. Its labels define the stable steps; visual-review-directed content replanning may shorten only their details while retaining label order and scientific bindings.

Keep mathematical content grounded in the complete source and preserve its operators, grouping, subscripts, exponents, conditions, and qualifiers. Prepared equation references are optional transcription shortcuts, not permission gates. Write source-grounded inline mathematics with explicit delimiters and display equations as LaTeX with source labels; never leave caret notation, commands, or ASCII subscripts visible. Inline math is for short notation that reads with a sentence or table row. When a contribution, mechanism, or guarantee depends on parsing a complete expression, use one equation carrier and keep nearby prose to its interpretation. If an expression is not legible enough to transcribe reliably, state only its supported qualitative meaning. Retain only essential expressions that remain readable at poster scale. The shared converter renders exact LaTeX as native semantic MathML and keeps it in `data-latex`; native hosts use the [equation-fragment command](#native-equation-fragments) rather than hand-transcribing the math tree. Use `<math display="block">` for standalone equations and `<math display="inline">` for notation within prose. The neutral content-carrier serializer recognizes `\(...\)` and `$...$` in text-grounded scientific copy through maintained delimiter parsers and the same MathML backend; it never infers equations from unmarked text. Do not override MathML's inner display type with ordinary CSS block, flex, grid, or inline-block. Give a long equation more inline measure or a wider span before reducing type. If its source semantics permit line breaks at relation operators, use `mtable`/`mtr`/`mtd` to align the source-equivalent lines. Escape a less-than operator as `&lt;` inside MathML. Unconvertible inline source remains visible for correction rather than creating another draft gate. Remote MathJax/KaTeX, scripts, and equation screenshots are not valid authoring. PPTX export converts each complete MathML expression into native editable Office Math without an image fallback; mixed text uses the existing measured text objects, including inside otherwise native tables.

`table.view="comparison"` is a carrier choice, not a formatting upgrade. Use it only when aligned magnitudes are the module's primary reading task and every displayed numeric column belongs to the same comparison frame. Its existing columns and rows remain the only data: finite nonnegative value columns render as aligned bars with independent zero-based scales, unchanged row identities, literal values, and units from the headers. Otherwise retain the literal table; missing, signed, uncertain, nonnumeric, or all-zero measures must also remain literal. Do not remove qualifications to obtain a chart. Marks and labels export through the existing editable shape/text path, not a second chart renderer or a linked spreadsheet chart. As with scientific figures, visual revisions must preserve the mapping between values, scales, labels and marks; changing a displayed value requires updating its plot, not just editing the label. The text snapshot does not independently certify that geometric mapping.

For automatic sizing, start from common academic bounds, including landscape formats up to 2:1, and treat the first area estimate only as an orientation and maximum-capacity heuristic. Audit the draft evidence budget against that physical capacity, then estimate the final page from the reduced budget. Predicted occupancy remains planning context rather than a pre-render acceptance gate; the final main-model audit makes editorial cuts, and Chromium plus visual review judge the actual composition. Preserve an explicit page unchanged. The estimator selects one direction from coarse predicted overflow, occupancy, common-page area, and selected-figure shape; those signals do not accept or reject the rendered poster. Preserve an explicit orientation unchanged. Content-shape affinity selects exactly one reference inside that direction. No host-side resolver creates, folds, balances, or ranks target lanes: the author model chooses the complete topology from the transferable spatial grammar and the grounded modules' actual depth. Chromium measures the authored result, and its diagnostics return to that same model for a bounded edit sequence. A `design-ready` recovery recreates authoring from the saved plan; `author-ready` recovery reuses the saved HTML. Compact means content-bounded, not small type.

Choose locally available font stacks that express the reference's typographic relationship and the user's preference; serif display with sans body, all-sans, or a restrained hybrid can all work. Never fetch a font. Avoid novelty or ultra-condensed display faces for long titles and module headings. Concrete CSS colors belong to the author model and should preserve the observed field-to-surface relationship while leaving scientific figure colors intact. No palette enum or swatch library constrains normal authoring. Treat role sizes and line measures as advisory conference-viewing evidence evaluated from the screenshot. Footer priority controls reading order, not permission to shrink substantive limitations below body scale. Give wide multi-panel plots enough physical width for axes and legends or omit them. Use the single `focal` module priority for the dominant entry point; do not manufacture another focal marker or limit the poster to a single visual emphasis.

Size prominent copy from its rendered shape, not from a fixed character-width template. When a title or central claim wraps awkwardly, widen its measure or rebalance adjacent groups before reducing type.

## Common layout pitfalls

- `flex: 1` includes positive `flex-grow`; on semantic columns it often forces equal heights and leaves the shorter column empty at the bottom. For a bounded column of poster modules, use intrinsic items (`flex: none` or `flex: 0 0 auto`) so a module frame cannot shrink below its content; keep `min-width: 0` on inner prose wrappers for horizontal wrapping.
- A flex/grid parent defaults to cross-axis stretch in common configurations. Use `align-items: flex-start` when columns must remain independently compact.
- `gap` combined with growing children makes the location of spare space hard to predict. Keep gaps explicit and let content define column height.
- A prose-bearing flex child with `flex: 0 0 auto`, a content-sized minimum width, or `white-space: nowrap` can expand beyond a narrow rail. Put `min-width: 0` on text-bearing flex/grid children and use wrapping or `minmax(0, 1fr)` tracks for compact comparisons.
- Fractional rows inside content modules, fixed `min-height`, and `justify-content: space-between` can distribute blank space while wrappers appear full. Use fractional tracks only when every track contains real content; module interiors remain intrinsic.
- `min-height: 0` on a content-bearing grid item allows the item box to shrink below its prose and figures, so children visibly spill into the next row even when the grid itself appears to fit. Keep poster modules intrinsically sized.
- Giving several direct grid children only `grid-column` does not create a coherent macro composition: auto-placement keeps advancing the row cursor, so a later group can start halfway down the page. Assign both grid axes explicitly or nest modules inside intrinsic scan-section groups.
- Do not mix direct modules and track wrappers in the same body grid, or place later modules in rows whose height is fixed by an unrelated focal item. The tallest item then stretches shorter content into visible voids. Prefer independently flowing groups when module heights differ.
- Choose column breaks from rendered intrinsic height and actual section headers, not equal module counts. Preserve a clear reading entry and ending while distributing independent evidence by measured demand; several tall figures in one column and short text in another is not a balanced scaffold.
- A reference's literal lane count is observed design evidence, not a code-selected quota. Follow the user's requested fidelity; for a new composition, adapt its dominance, grouping, rhythm and asymmetry to the target evidence and actual module depth.
- Use a track-wide section header only when the modules beneath that track have comparable intrinsic depth. Otherwise attach section cues to compact local groups so one short section cannot create an empty column beside an overflowing one.
- Focal prominence does not always require a span. It may come from evidence scale, module depth, position, measure, or contrast; a colored heading alone is insufficient.
- `max-width: 100%` prevents overflow but does not enlarge a prepared SVG or raster figure beyond its intrinsic size. Give evidence figures an explicit responsive width when the available module measure should be used; otherwise an A0 poster can contain technically valid but unreadable thumbnails and a large unused lower field.
- Report physical figure dimensions, image-box dimensions, painted fractions, and actual rendered typography distributions as conference-viewing context, not universal readability thresholds. Whole-page figure-area percentage and code-derived typography targets are not sent as reviewer evidence because neither establishes whether concrete marks or text are readable. Figure area remains internal crop-selection salience; typography targets remain authoring context and advisory browser diagnostics. The reviewer judges the actual marks and type in the full candidate overview with detail crops only as inspection aids. Valid hashes, nonzero rendering, visibility, and an unclipped in-page image remain hard source-evidence requirements.
- A poster with `width: 841mm` may still shrink to the browser viewport because flex items default to `flex-shrink: 1`. Keep the body-level poster root outside a shrinking flex context or set `flex: none`; Chromium must measure the declared physical dimensions.
- Do not fix these traps by stretching an empty wrapper. Chromium records geometry and type measurements; the screenshot reviewer judges whether the remaining space, hierarchy, and readability are purposeful.

## Complete HTML contract

- Begin with `<!doctype html>` and return the entire document without Markdown fences.
- Use one body-level `main`, `article`, or `div` poster root with `data-poster-id` and inline CSS with `@page` size in millimetres. The root encloses the complete poster: exactly one compact `data-poster-title-band` followed by the internal evidence body. “Outside module styling” never means outside this root. The root itself must render at the declared physical width and height; use `@page` margin `0`, put print margins in root padding, and use `box-sizing: border-box` when the root owns padding or borders. Prefer semantic `main` or `article`.
- Give every independently placeable evidence module one stable `data-poster-module` wrapper and `data-poster-id`. The wrapper is an audit, selection, and export anchor, not necessarily a visible panel. Several modules may share one section and group-level heading; the author model may regroup intact modules while preserving their bindings.
- Preserve the audited carrier metadata on every module: `data-semantic-roles`, `data-module-priority`, and `data-visual-kind`. The one module whose priority is `focal` is the planned distance-level entry; no separate focal attribute exists. Any sourced focal element must carry or inherit a verifiable `data-source-label`. The author may create additional visual emphasis without changing these scientific planning fields.
- Give meaningful selectable elements stable unique `data-poster-id` values. Every evidence-bearing `data-poster-module` needs a non-empty `data-source-label` copied from the source's own provenance vocabulary. Machine validation does not infer grounding from one English locator regex; prepared figure hashes and equation bindings remain the authoritative identities.
- Embed supplied PNG, JPEG, GIF, WebP, or safe SVG figures as data URIs. Treat prepared source figures as a provenance manifest and render only the grounded subset explicitly selected by evidence planning; a poster may remain text-, equation-, or table-led when no figure earns readable area. Place each selected figure wherever it best supports its grounded interpretation; its hash and provenance travel with it rather than binding it to an original layout slot. A network-capable harness may download an authorized asset and pass its local path through `assets`; portable authoring itself never fetches remote content. `asset://N` is only a transient host token resolved before persistence.
- Place a short grounded interpretation beside or below each selected figure or coherent figure group. When a module already supplies that reader-facing interpretation, do not repeat the paper-original caption beneath its figures; the complete caption remains in image alt/provenance metadata. A multi-figure module uses one shared interpretation only when the relationship among those carriers is itself the evidence. The paper locator stays in `data-source-label` and the consolidated provenance/references module. Apply decorative corners to surrounding panels, not to source-figure pixels: retain the complete rectangular source image in HTML and editable export.
- Do not include scripts, event handlers, forms, animation, imports, external fonts, remote URLs, placeholders, or executable SVG. Scientific copy stays explicit DOM text. Native list-style identifiers are supported; custom counter styles, list strings/functions/images and authored CSS `content` are not. `content:normal` or suppression does not author new copy.

## Native equation fragments

For Codex, Claude Code, or an explicitly selected native Omni authoring session,
copy the selected inventory expression's `latex` value into a UTF-8 file without
changing its notation. Convert it with the same `latex2mathml` backend used by the
engine's content carrier:

```bash
python "<skill-dir>/posterlib/content/equations.py" --latex-file equation.tex > equation.mathml
```

Use `--display inline` for inline notation. On success, insert the returned `<math>`
fragment unchanged into the model-authored HTML; retain its `data-latex` and the
owning module's source locator. The model chooses its size, surrounding space and
placement. This preserves grouping, fences, limits and editable Office Math without
equation images or a second renderer. Hand-written unsupported `<mfenced>` is not a
browser-supported substitute: its implicit brackets and separators disappear in
Chromium. A conversion error goes back to the exact source, not a guessed formula.

## Revision

Carry the original user direction through revision checkpoints and supply it to the
author alongside the current request. It defines unchanged requirements, not a command
to redo earlier edits. A current explicit change takes precedence over conflicting
earlier requirements. This author context is separate from the operational screenshot
reviewer's current-state evidence; it does not replay reference pixels in that review.

Omni also offers `replace_poster_stylesheet` for a complete CSS reflow without
retyping the scientific DOM. Supply all page CSS, including `@page`; the HTML parser
replaces existing style elements while preserving body content and inline attributes.
Exact edits remain available for local changes. For structural work,
`replace_poster_layout` accepts a wrapper shell with `data-poster-ref` placeholders and a
complete stylesheet; the host reinserts the exact current title band and module nodes.
The same static and Chromium inspection runs after each operation. Codex and Claude Code
perform the equivalent wrapper and stylesheet edit with their native file tools.

Keep the editor's native assistant/tool exchanges intact, including call ids and a
result for each requested operation. A bounded context window starts with the HTML
checkpoint from before its retained exchanges; those exchanges determine the current
state. Recasting completed calls as fresh user prose loses this execution context
and can make the model repeat an already-applied edit.

Revise the exact source HTML after verifying its hash. The current HTML is the operational design state. During a full-layout edit, the author reads the actual headings and scientific copy in the current HTML so it can compose around their meaning and length. Only embedded image bytes become transient asset tokens; figure identity, aspect ratio, alt text, and DOM ownership stay visible, and the exact image bytes are restored before validation and render. The existing scientific snapshot protects copy and bindings without hiding text from the author. Physical readability references expose measures such as usable width and type scale, not a code-chosen column count or target topology. The already interpreted ReferenceAnalysis remains author context during every revision, including reflow and local edits. Its observations preserve the requested design relationship rather than authorizing a new restyle or freezing a target topology; current explicit user changes take precedence. A custom reference image accompanies operational review as a visual-quality comparison, without re-running its design interpretation or transferring scientific content. The author receives the reviewer's concise visible-defect summary, issue criterion, target, operation, and host-bound observations, then chooses the visual solution from the current HTML. The summary diagnoses the current screenshot and reading impact only; strengths and any solution topology remain human-facing receipt context. A selection may contain only stable poster id, nearest evidence module, optional audit hints, text sample, rectangle, and styles. Each visual edit batch uses unique exact replacements for local work, a complete stylesheet for visual reflow, or an atomic layout shell plus stylesheet for wrapper topology. The layout shell contains only wrappers and references to current scientific nodes; the host restores those exact nodes before validation. Each reference is an empty replacement marker with no other attributes, so layout classes and styles belong on its retained parent wrapper. The editor may continue from a statically valid proposal that reduces a blocker or changes the governing parent relationship without adding or increasing another blocker, while the best checked delivery checkpoint remains available. A proposal with the same blocked relationship and no measured improvement is discarded. Never accumulate duplicate selector overrides. Presentation-only title `<br>`/`<wbr>` tags may be inserted, moved, or removed while the decoded verified title remains exact; a wide unoccupied masthead should not retain manual breaks that leave every line needlessly short. Table span follows the table's scientific role and comparison task rather than column count alone: a supporting numeric table must not displace primary figures merely because it has many columns. Targeted content-replan may additionally rewrite only body text, ordinary detail points, and method-step details in named modules; method-step labels and order, headings, takeaways, captions, tables, and equations remain frozen. The editor lists the structured copy fields that actually exist for every target module; use only those fields instead of inferring a channel from module type or prose. The host stages each batch, validates and renders it, then returns Chromium diagnostics and the current HTML for another batch when necessary. Source-figure/text collision feedback identifies the colliding text element, exact rendered text-line and figure boxes, and the crossed edge so the model repairs the owning boundary rather than unrelated downstream spacing; these facts do not prescribe a layout. When baseline measurements are available, each edit result compares current physical source-figure extents with the inspected revision source, or with the latest reviewed candidate after a visual-review receipt; the feedback identifies its baseline. The editor owns HTML edits and deterministic browser measurements only. The first candidate that clears deterministic blockers returns to the workflow automatically. The workflow reviews the incumbent and proposal in one VLM call and promotes only an overall improvement. An unchanged or regressed proposal leaves the incumbent selected and triggers a different-strategy edit while the shared deadline permits; the loop stops on pass, unavailable review or authoring, or resource exhaustion. A visually imperfect but geometrically valid candidate remains available as an explicitly unapproved HTML/PPTX. Failed geometry and visually unchanged or regressed proposals never replace the published candidate. Each staged candidate carries its own source-bound sidecar; the task checkpoint records completed stages, not the latest unselected proposal. A later revision restores the selected HTML's sidecar, never an unrelated workspace checkpoint.

The initial content budget remains checkpointed for planning history and source bindings; it is not a second current-copy authority. Review the actual HTML snapshot. Global selection ends with the first rendered candidate. Later automatic and public revisions freeze that scientific snapshot unless a receipt targets explanatory copy for `content-replan`; that operation may compress or reorganize only the named current copy without changing its conclusions or retained qualifiers. A user-directed content-replan may instead correct or clarify the requested target copy from the complete bound source, including a mistaken heading or takeaway. Neither path rebuilds the whole page from the original budget; preserve existing CSS and layout except for required local fit changes. Structural validation does not independently certify scientific claims.

Before a model-backed revision, replace embedded image data URIs with transient `asset://N` tokens and restore the exact bytes afterward so figures do not consume the model context. Revision recovers source text and prepared assets from the selected HTML sidecar, including in a new process without a task id. Overflow returns the existing geometric feedback; publication does not silently shrink type or run a second fit mutation.

## Runtime and transport controls

`workflow_timeout_seconds` configures the shared action deadline (default 3590, maximum 3600 seconds); a shorter live host envelope wins. Before planning starts, the workflow reserves up to 90 seconds (at most 20% of a shorter envelope) for editable PPTX export. Planning, editing and visual reviews share the remaining absolute deadline. `authoring_timeout_seconds` bounds each initial or revision editor call (default/maximum 900 seconds), and `authoring_transport_retries` controls transient transport retries (0–2). Increasing an allowance never resets a deadline. Evidence-plan validation repairs continue while the response changes and the shared deadline permits; `max_repair_attempts` optionally caps those repairs (range 0–10). The stateful HTML editor is bounded by the remaining shared deadline rather than a fixed turn count and validates every proposal before promotion.

The editor prefers native tool calls. A chat-only host, or the first native request failing before any edit, uses one JSON command per ordinary non-streaming text response: `{"name":"apply_poster_edits","arguments":{"edits":[{"old":"exact old text","new":"new text"}]}}`. All editor commands retain the same dispatcher, scientific-content checks, Chromium measurements, and automatic handoff of the first reviewable candidate. A transport fallback never authorizes additional edits or relaxes acceptance.
